1,064 commits after 0.1.0, we're happy to announce the first release
candidate of Ponko 0.2, [on crates.io](https://crates.io/crates/ponko/0.2.0-rc.1)
now!

Ponko is a 2D and 3D game engine written in Rust, with a C and C++ API on
top. Start with [the guide](/guide/), browse
[the source](https://github.com/ponkoengine/ponko), or play the demo on
[our home page](/). It's free and open source forever!

A release candidate means 0.2 is feature complete. From now on `main` only
takes fixes for regressions: things that worked before and don't now. If a
week passes without one, 0.2.0 ships with nothing changed but its version
number. If something turns up, we fix it and publish RC 2.

Two weeks ago we wrote that [the next release waits for proof, not
features](/blog/fewer-releases-better-ones/). This week is where that proof
comes from, and it needs _you_. We've checked Ponko on our machines, but
only people running it on theirs, with their own projects, can tell us it's
ready. Make a copy of your project before you upgrade, or better, keep it in
version control.

## Highlights

There's a _lot_ in 0.2. It turns Ponko from a fast 2D and 3D core into an
engine you can ship a whole game with, and the simple path stays the same:
`Game::new()`, a few systems and `.run()`. Here are some of the highlights:

- **The editor:** `ponko editor` edits 2D and 3D scenes and prefabs, with
  undo, an asset panel and glTF scenes ([guide](/guide/editor.html)).
- **Game structure:** an [entity hierarchy](/guide/hierarchy.html),
  [game states](/guide/states.html), component hooks, required components
  and [plugins](/guide/plugins.html) for other people's crates.
- **Rendering:** 2D lights, a [water kit](/guide/water.html), baked and
  probe lighting, glTF material layers, temporal upscaling and
  [HDR output](/guide/hdr.html).
- **Crowds:** [thousands of animated characters](/guide/crowds.html) in a
  few draw calls, plus [2D skeletons](/guide/skeleton2d.html) and humanoid
  retargeting.
- **UI:** a [widget set](/guide/ui-widgets.html), text shaping, IME,
  [localization](/guide/localization.html) and screen readers on Windows and
  Linux.
- **Multiplayer:** [rollback](/guide/multiplayer.html), replication, client
  prediction, [dedicated servers](/guide/servers.html), a lobby server,
  WebRTC and Steam.
- **More platforms:** [iOS](/guide/ios.html), [Android](/guide/android.html),
  threads on the web, and WebGPU first in the browser.
- **Shipping:** `ponko new` and `ponko package`, crash reports with native
  backtraces, mods, and error messages that tell you the fix.

The [release notes](/guide/release-0.2.html) cover all of it, area by area,
each linked to its chapter in the guide. Then there are two tutorials, a
cookbook of fifty recipes, [Coming from Bevy](/guide/from-bevy.html) and
three reference games to learn from.

The rest of this post covers what changed in the last week, while we ran
the checks for this candidate.

## Compute Readback

Authors: [@cacheleon](https://github.com/cacheleon) · PRs: [#702](https://github.com/ponkoengine/ponko/pull/702)

Compute passes are great for big simulations: a fire spreading over a grid,
water, a crowd. But their state lives on the GPU, and until now a game had
no way to read any of it. So the rules couldn't know that a house was on
fire, or that 62% of the forest was saved.

Now you can ask for a few values and get them a few frames later:

```rust
// Ask for the 4 x 4 region counts. The answer comes later.
let pending = ctx.gfx.read_render_target(regions, UVec2::ZERO, UVec2::new(4, 4));

// On a later frame:
if let Some(Ok(values)) = ctx.gfx.readback(pending) {
    let burning: f32 = values.iter().map(|v| v.x).sum();
}
```

It's asynchronous on every backend, on purpose. A read that waits for the
GPU stalls the pipeline on native and can't happen at all in a browser, so
there's no blocking version, and a game behaves the same everywhere.

Two things to know. Read a handful of values, not the whole grid: add the
grid up in a second compute pass first, as
[the guide](/guide/3d.html) shows. And keep readback values out of
deterministic simulation, since GPUs round differently. They're for visuals,
UI and single-player rules, not for rollback or lockstep.

## 3D in the Browser

Authors: [@cacheleon](https://github.com/cacheleon), [@damix00](https://github.com/damix00) · PRs: [#703](https://github.com/ponkoengine/ponko/pull/703), [#711](https://github.com/ponkoengine/ponko/pull/711)

The candidate's checks caught a big one: 3D canvases were blank in every
browser on WebGPU. A branch in the built-in material shader looked uniform
to the native shader compiler, but browsers judge uniformity more strictly,
rejected the shader, and with it every 3D pipeline. Desktop was fine, which
is why nothing else noticed.

#703 fixes the branch. #711 goes further: the shader code shared by every
material and compute pass no longer uses implicit screen derivatives at
all, so a later change can't bring the problem back. A test now checks for
it, and the render tests' 41 images came out byte-identical.

## Buffers on iOS Safari

Authors: [@damix00](https://github.com/damix00) · PRs: [#710](https://github.com/ponkoengine/ponko/pull/710)

Safari on iOS sometimes hands back an empty range when a buffer is filled at
creation, and the game stopped while starting. On WebGPU, new buffers are
now filled through the queue instead. Native keeps the faster path.

## Smaller Fixes

- **Windows:** skeleton file paths, a network test's receive buffer, the
  WebRTC test switch and the C library's self-test (#692, #706).
- **Linux:** native crash reports without line tables, and the Arm C
  library with video (#697).
- **Rendering:** a 3D frame holding only compute passes skipped them (#702).
- **Tests:** tests that assumed version 0.1.0 now pass at a candidate's
  version (#700, #704, #705).

## What We Checked

Our last post listed what a release has to prove. Here's where RC 1 stands:

- **macOS** (Apple Silicon, Metal): the full list of checks passed on the
  release branch, including Miri, the address and undefined-behaviour
  sanitizers, all 17 fuzz targets, and the browser runs in Chromium and
  WebKit.
- **Windows:** earlier full runs with DirectX 12 and Vulkan found the Windows
  problems fixed above. A full run on an NVIDIA card is in progress.
- **Linux:** the C libraries for x86_64 and Arm were built and tested in
  containers. The full list hasn't run on a real Linux machine yet.
- **People:** no newcomer has followed the guide yet, and the hardware checks
  (controllers, displays, HDR) are still open.

0.2.0 doesn't ship until the full list passes on all three.

## Downloads

Cargo never picks a release candidate unless you ask for it by version, so
a plain `cargo add ponko` still gives you 0.1.

<Steps>

1. **In an existing project:**

   ```sh
   cargo add ponko@0.2.0-rc.1
   ```

   Add `--features 3d` for 3D. When RC 2 or 0.2.0 comes out, `cargo update`
   moves you to it.

2. **For a new project,** install the command-line tool and start from a
   template. The templates already depend on the candidate:

   ```sh
   cargo install ponko_cli --version =0.2.0-rc.1 --locked
   ponko new my-game
   ```

3. **From C or C++:** the C library for macOS (Apple Silicon and Intel) and
   Linux (x86_64 and Arm) is on the
   [GitHub release](https://github.com/ponkoengine/ponko/releases/tag/v0.2.0-rc.1),
   with checksums. Windows downloads follow there shortly.

</Steps>

<Callout type="note" title="A candidate is still a pre-release">
  We think RC 1 is ready for real projects, but it isn't a stable release
  yet. Keep your project in version control, and expect an RC 2 if testing
  turns something up.
</Callout>

## Known Issues

During the candidate week we fix only regressions. These are the ones we
already know about:

- **3D in Safari 26 on WebGPU:** after the fixes above, some 3D scenes still
  lose the GPU device or freeze right after they start in Safari on macOS
  (#701). Chromium draws them.
- **Render tests on non-Apple GPUs:** the last part of #497 waits for the
  NVIDIA run.

The [issue tracker](https://github.com/ponkoengine/ponko/issues) has every
known bug.

## Bug Reports

Found something? Please [open an issue](https://github.com/ponkoengine/ponko/issues/new/choose).
Search first in case it's known, and put "0.2.0-rc.1" in the report. A bug in
something that worked in 0.1 is the most useful report you can send this
week. So is a two-line note that the candidate builds and runs on your
machine: we only have a few.

When an AI coding agent edits a game, it normally can't see the game. It
reads the code, changes something, and has no way to check the result. If
something breaks at runtime, it adds print statements and asks you what's on
the screen.

`ponko-mcp` is our fix for that. It's a
[Model Context Protocol](https://modelcontextprotocol.io) server, so it works
with any MCP client (Claude Code, Cursor, Codex and so on). The agent can use
it to start your game, look at what's going on inside while it runs, change
things, and step the simulation one tick at a time. We wrote the first
version on the engine's first evening and have kept adding to it. This post
covers what it does now.

## Setup

<Steps>

1. Install the server.

   ```sh
   cargo install ponko_mcp
   ```

2. Add it to your agent. For Claude Code:

   ```sh
   claude mcp add ponko -- ponko-mcp
   ```

   Other clients take the same command, `ponko-mcp`, over stdio.

3. Mark the components you want the agent to see as reflected.

   ```rust
   ctx.world.reflect::<Health>();
   ```

</Steps>

## What it can do

By default it launches games headless and paused, so nothing happens until
the agent asks for it. Then the agent can:

- Read the world. It can list entities, filtered by components or by
  conditions like `Health.current < 5`, read a single entity, read resources
  like the score, and get statistics over everything that matches, e.g. how
  many units each team has and how damaged they are.
- Control time: pause, resume, change the speed, or run exactly N ticks and
  wait for them. `watch` runs ticks while sampling resources and entity
  counts.
- Change things: spawn and despawn entities, set components and resources,
  and save or load worlds, scenes and prefabs.
- Follow what happened by subscribing to the game's events, reading its logs
  and taking screenshots it can look at.
- Profile: per-system timings, frame-time percentiles, GPU time per render
  pass, a Perfetto trace of the next few frames, and whether the last shader
  edit compiled (with the line and column if it didn't).
- Play. It can run a scripted sequence of key, mouse and gamepad input at
  given ticks, with checks in between. If a check fails, it reports the step,
  the tick and what it expected.

<Callout type="tip" title="Watch-only agents">
  Start the server with `ponko-mcp --read-only` and every tool that changes the
  game is hidden. The agent can look and measure, but can't touch.
</Callout>

## Why we built it

An agent needs the same loop a person does: make a change, run it, see what
happened, measure. The MCP server turns each of those steps into a tool call,
so the agent doesn't have to guess.

We use it on the engine too. The first thing we tried was pointing an agent
at the boids example. It found a few rough edges, and we fixed them that day.

Under the hood the server uses two things you can also use directly: a
token-protected [control endpoint](/guide/control.html) on localhost, and
[reflection](/guide/reflection.html), which reads and writes components by
name as JSON. The full list of tools is in the guide's chapter on
[working with agents](/guide/agents.html).
